# Blocking ask_owner tool with resume-based crash recovery

A headless session asks the owner a question via the `ask_owner` MCP tool, which blocks until the phone answer arrives. We rely on ask_owner being a **local stdio** MCP server: Claude Code's 5-minute idle timeout applies only to remote (HTTP/SSE/WebSocket) servers, and the wall-clock cap is the per-server `timeout` field in the MCP config (default ~28h via `MCP_TOOL_TIMEOUT`), which we set explicitly (~8h). Verified against code.claude.com/docs/en/mcp.md, 2026-07-04.

The rejected alternative — end the turn on every question and `--resume` with the answer — survives restarts by construction but replays the entire conversation on each round, which multiplies subscription-quota burn under unlimited-escalation grilling. Instead, resume is the **fallback only**: the bot records `session_id` (from `--output-format json`) and the worktree path in the ledger comment *before* relaying a question, so a dead blocked session is recovered with `claude -p --resume <id> "owner answered: X"` from the same worktree (resume lookup is scoped to the original project dir/worktrees — the worktree must not be pruned while a question is pending).
